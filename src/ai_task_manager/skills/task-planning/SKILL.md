# task-planning

## Назначение
Помочь пользователю решить, что делать сначала. Результат — порядок задач и короткие
причины. Задачи при этом не меняются.

## Когда применять
Только для вопросов о порядке выполнения (`plan_tasks`). Создание, изменение и удаление задач
планирует код, этот скилл для них не нужен.

## Порядок работы
1. Найди задачи, которые можно начинать сейчас: у них пустой `blocked_by`.
2. Среди них выбери первую по правилу:
   - просроченная (`days_left` меньше 0), из нескольких — самая давно просроченная;
   - срок ближе всего (меньший `days_left`);
   - от задачи зависят другие (непустой `blocks`);
   - приоритет: `high`, потом `medium`, потом `low`;
   - задачи без срока и без приоритета — в последнюю очередь.
3. Поставь выбранную задачу в порядок. Задачи, которые её ждали, могут стать доступными.
4. Повторяй с шага 1, пока не расставишь все задачи.
5. Для каждой задачи напиши причину из её фактов.

## Типичные ситуации
- **Конфликт сроков:** зависимая задача должна быть сдана раньше той, от которой зависит.
  Порядок всё равно по зависимости. В сообщении предупреди о конфликте, сроки не предлагай
  менять.
- **Срочная задача ждёт другую:** сначала та, которую она ждёт. Причина: «нужна для задачи #N
  со сроком через M дней».
- **Предпочтение «удобно вечером»:** упомяни в пояснении, порядок из-за него не меняй.
- **Одна задача:** порядок из одной задачи, причина — её срок или приоритет.

## Частые ошибки
- Писать «срок завтра», когда `days_left` не равен 1.
- Упоминать приоритет у задачи с `priority: null`.
- Рекомендовать приоритет задаче, у которой он уже задан.
- Пропускать задачи или повторять одну задачу дважды.

## Проверка перед ответом
- [ ] Каждая задача из `tasks` встречается в `ordered_task_ids` ровно один раз.
- [ ] Ни одна задача не стоит раньше задачи из своего `blocked_by`.
- [ ] Каждая причина совпадает с `days_left`, `priority`, `blocks` этой задачи.
- [ ] В сообщении есть предупреждение, если `conflicts` не пустой.
