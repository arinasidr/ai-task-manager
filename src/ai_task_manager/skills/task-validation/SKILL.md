# task-validation

## Назначение
Решить, можно ли выполнять план: делает ли он ровно то, что просил пользователь. Валидатор
не исправляет план, а называет проблему так, чтобы планировщик мог её исправить.

## Когда применять
Для планов, которые меняют задачи или предлагают порядок выполнения. Планы только на чтение
и уточняющие вопросы код принимает без модели.

## Порядок работы
1. Прочитай `request` и выпиши для себя, что просил пользователь: действие, какие задачи,
   какие сроки, приоритеты, названия.
2. Сравни это с `plan.operations` по каждому пункту. Лишнее в плане — `invented_data`,
   недостающее — `missing_data`, не та задача — `wrong_task`, не то действие —
   `intent_mismatch`.
3. Сроки: если в `verified_by_code` даты уже проверены — пропусти этот шаг. Иначе найди слово
   из запроса («пятница», «через неделю») в `calendar` и сравни дату с `deadline` в плане.
4. Прочитай `message_to_user`: нет ли там «готово», «удалено», «создано» до выполнения.
5. Для порядка выполнения сравни каждую причину с фактами задачи в `tasks`.
6. Нет проблем — `accept` и пустой `issues`. Есть — `reject` и по одной записи на проблему.

## Что не является ошибкой
- Конкретная дата в плане вместо «завтра» или «в пятницу» — так и должно быть.
- Срок без времени, если пользователь время не называл.
- Отсутствие приоритета, если пользователь его не называл.
- Название задачи с другой заглавной буквой или без слов «задача», «добавь».
- Порядок операций в плане, формулировки и стиль сообщения.
- То, что уже проверил код: существование ID, циклы, подтверждение удаления.

## Как писать замечание
`detail` — одно предложение: что не так и как должно быть. Например: «В плане приоритет
high, а пользователь приоритет не называл — приоритета быть не должно».

## Проверка перед ответом
- [ ] Каждое замечание указывает на конкретное расхождение с запросом.
- [ ] Нет замечаний из списка «что не является ошибкой».
- [ ] Не противоречишь себе: если дата в плане совпадает с нужной — это не ошибка.
- [ ] `decision` — `reject` только при непустом `issues`.
